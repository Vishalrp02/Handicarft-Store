# API Gateway Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `subagent-driven-development` (recommended) or `executing-plans` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build `services/gateway`: the single public entry point. It routes `/v1/*` by prefix to services, enforces CORS, security headers, rate limits and early JWT rejection, blocks `/internal/*`, strips spoofable headers, passes the Razorpay webhook through byte-for-byte, and aggregates health and OpenAPI docs.

**Architecture:** A stateless Express app (no database, no broker) built with `createHttpApp`, but with **body parsing disabled**, so proxied bodies stream untouched. Proxying uses `http-proxy-middleware` v3. Rate limits live in Valkey (shared across restarts).

**Tech Stack:** service-kit, `http-proxy-middleware`, `cors`, `express-rate-limit` + `rate-limit-redis`, `iovalkey`.

**Spec:** `02-target-architecture.md` §5.1, §6; `03-api-and-event-contracts.md` §1; prefix ownership in `02-target-architecture.md` §4.

**Prerequisite:** plan 02 complete. Services are not required (tests use stub upstreams).

**Required skills:** `safe-backend-changes` (first), `nodejs-backend-patterns`, `api-design-principles`, `auth-implementation-patterns`; plus the workflow skills `test-driven-development`, `systematic-debugging`, `verification-before-completion`, `requesting-code-review`. Use **only** the project skills in `.claude/skills/` (mirrored in `.agents/skills/`); no other skills or plugins. See `docs/architecture/05-engineering-standards.md` §8.

## Global Constraints

- Port 8080. Config: `BaseConfigSchema` + `VALKEY_URL, CORS_ORIGINS (comma list), IDENTITY_URL, CATALOG_URL, SELLER_URL, CART_URL, ORDER_URL, PAYMENT_URL, PROXY_TIMEOUT_MS=15000, TRUST_PROXY_HOPS=1, DOCS_ENABLED=false`.
- Route table: **longest prefix wins**; the order matters and is tested:

  | Prefix | Upstream |
  |---|---|
  | `/.well-known/jwks.json`, `/v1/auth`, `/v1/me`, `/v1/admin/users` | identity |
  | `/v1/seller/products`, `/v1/categories`, `/v1/products`, `/v1/admin/products`, `/v1/admin/categories`, `/v1/admin/reviews` | catalog |
  | `/v1/seller/orders`, `/v1/checkout`, `/v1/orders`, `/v1/admin/orders`, `/v1/admin/seller-orders`, `/v1/admin/stats` | order |
  | `/v1/seller`, `/v1/sellers`, `/v1/admin/sellers`, `/v1/admin/payouts` | seller |
  | `/v1/cart`, `/v1/wishlist` | cart |
  | `/v1/payments`, `/v1/webhooks`, `/v1/admin/payments`, `/v1/admin/refunds` | payment |

- Any path containing `/internal` (case-insensitive, after URL-decoding) → 404 `NOT_FOUND`. Unknown `/v1/*` → 404.
- Stripped from inbound requests: `x-internal-token`, `x-user-id`, `x-forwarded-user`, any `x-craftoria-*`. Set: `x-request-id`, `x-forwarded-for` (client IP from `CF-Connecting-IP`, else the socket address).
- Rate limits (Valkey store, key = client IP): global 300/min; `/v1/auth/*` 20/min; `/v1/checkout` 10/min per user (key = token `sub`, else IP). The Razorpay webhook is exempt from rate limits and CORS.
- JWT: if `Authorization: Bearer` is present, verify it with `createJwtVerifier` (JWKS from `IDENTITY_URL/.well-known/jwks.json`). Invalid → 401 `UNAUTHENTICATED` without proxying. **Missing** tokens pass through; services decide.
- CORS: `origin` ∈ `CORS_ORIGINS`, `credentials: true`, methods `GET,POST,PUT,PATCH,DELETE,OPTIONS`, allowed headers `Authorization, Content-Type, Idempotency-Key, X-Requested-With, X-Request-Id`, exposed `X-Request-Id, Retry-After, Idempotent-Replayed`, `maxAge 600`.
- Upstream timeout or connection refused → 503 `UPSTREAM_UNAVAILABLE`, using the standard error body.

## Review Focus

1. `/v1/seller/products` must route to catalog, not seller (prefix collision). (Task 1 table test.)
2. `/v1/%69nternal/x`, `/V1/INTERNAL`, `/v1/cart/../internal/carts/1` → all 404. (Task 1 test `internal paths blocked in all encodings`.)
3. The webhook body must arrive byte-identical, or Razorpay signatures fail. (Task 1 test `webhook body forwarded byte-for-byte`.)
4. A client-sent `X-Internal-Token` must never reach an upstream. (Task 1 test.)
5. Valkey down → rate limiting fails open (requests still flow, error logged) rather than taking the site down. (Task 2 test.)
