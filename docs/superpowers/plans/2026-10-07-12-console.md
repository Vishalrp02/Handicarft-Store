# Console (Artisan + Admin) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `subagent-driven-development` (recommended) or `executing-plans` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. UI tasks follow `impeccable` and finish with `web-design-guidelines`. The console is a working tool, so it is dense and calm; the storefront's editorial style does not apply.

**Goal:** Build `apps/console`, a single SPA with two role-gated areas. `/seller/*` lets artisans manage products, images and stock, fulfil orders, and see earnings and payouts. `/admin/*` lets admins approve sellers, moderate products and reviews, manage orders and refunds, run payouts, and manage categories and users.

**Architecture:** Vite + React SPA on Cloudflare Pages (`console.craftoria.in`). It uses `@craftoria/api-client` (including the shared `session`), TanStack Query for server state, TanStack Table for lists, and react-hook-form + contracts zod schemas for forms. Route guards use the token's `roles`/`sellerId`, and the server enforces them again.

**Tech Stack:** React 19, Vite 6, Tailwind CSS v4 (`@tailwindcss/vite`, theme from `@craftoria/ui/theme.css`; the only styling system), React Router 7 (library/SPA mode), TanStack Query 5, TanStack Table 8, react-hook-form, `@craftoria/ui`, `@craftoria/api-client`, MSW, Vitest + Testing Library.

**Spec:** `03-api-and-event-contracts.md` (all `/v1/seller/*` and `/v1/admin/*` endpoints); `02-target-architecture.md` §7.2–§7.5, ADR-8.

**Prerequisite:** plan 02 Tasks 1–4; storefront plan Task 1 (`@craftoria/ui`) and Task 2 (`@craftoria/api-client`).

**Required skills:** `impeccable` (build, then `critique` + `polish`), `handcrafted-storefront-ui` (tokens and copy only), `vercel-react-best-practices`, `web-design-guidelines` (final review); plus the workflow skills `test-driven-development`, `systematic-debugging`, `verification-before-completion`, `requesting-code-review`. Use **only** the project skills in `.claude/skills/` (mirrored in `.agents/skills/`); no other skills or plugins. See `docs/architecture/05-engineering-standards.md` §8.

## Global Constraints

- Dev port 5173. Env: `VITE_API_BASE_URL`, `VITE_STOREFRONT_URL`, `VITE_MEDIA_BASE_URL`, `VITE_API_MOCKS`.
- Guards: `/seller/*` requires `roles` ∋ `artisan` and `sellerId`; a buyer without them is redirected to `${VITE_STOREFRONT_URL}/sell`. `/admin/*` requires `admin`. Everything else → `/login`, the console's own minimal login screen using the same endpoints.
- After an approval flow, or whenever an API call returns 403 `FORBIDDEN`, call `session.refresh()` once (roles may have changed), then re-evaluate the guards.
- Every destructive or money-moving action (reject, suspend, cancel order, refund, mark payout paid) opens a confirm dialog that restates the effect, e.g. "Refund ₹2,450 to Asha R. for CR-2610-000123?". Admin actions require a reason where the API does.
- Lists use URL query params for filters and cursors so views are linkable.

## Review Focus

1. A seller's console must never show another seller's data even if the URL is edited; the UI relies on API 404s and shows "Not found". (Task 2 test.)
2. An image upload interrupted mid-way (PUT to R2 fails) leaves no confirmed image and shows a retry. (Task 2 test.)
3. Double-clicking "Mark shipped" sends one request (the button disables while pending). (Task 3 test.)
4. "Run payouts" twice in quick succession: the second click is disabled until the first resolves, and the list shows the result. (Task 5 test.)
5. A token that expires during a long form edit must not lose the form: silent refresh and retry. (Task 1 test.)
