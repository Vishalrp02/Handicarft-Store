# Storefront Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `subagent-driven-development` (recommended) or `executing-plans` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. For every UI task also follow `handcrafted-storefront-ui` + `impeccable` and finish with `web-design-guidelines` (project rule in `CLAUDE.md`).

**Goal:** Build `apps/storefront`, the buyer-facing site: SSR public pages (home, browse, search, product, artisan) for SEO and link previews; client-side account, bag, checkout with Razorpay, orders, and the artisan application. It replaces the legacy `frontend/`.

**Architecture:** React Router 7 in framework mode with SSR (Node adapter) in a container. Public routes use server `loader`s calling the gateway anonymously and return `Cache-Control: public, s-maxage=60, stale-while-revalidate=600`. Private routes use `clientLoader` with the in-memory access token. A shared `@craftoria/api-client` (typed by `@craftoria/contracts`) is used by both apps; its MSW mocks let UI work start before the services exist. Design tokens live in `@craftoria/ui`.

**Tech Stack:** React 19, React Router 7 (framework mode), TypeScript, Tailwind CSS v4 (`@tailwindcss/vite`; the only styling system, see `05-engineering-standards.md` §3), `@craftoria/ui`, `@craftoria/api-client`, react-hook-form + zod, MSW 2, Vitest + Testing Library, Playwright (+ `@axe-core/playwright`), Lighthouse CI.

**Spec:** `02-target-architecture.md` §3, §6 (frontend tokens), §7.1, ADR-7; `03-api-and-event-contracts.md` (all public endpoints); `.claude/skills/handcrafted-storefront-ui/SKILL.md` (brand direction, copy, AI tells to avoid).

**Prerequisite:** plan 02 Tasks 1–4. The services are not required until plan 15.

**Required skills:** `handcrafted-storefront-ui` (first), `impeccable` (build, then `critique` + `polish`), `vercel-react-best-practices`, `web-design-guidelines` (final review); plus the workflow skills `test-driven-development`, `systematic-debugging`, `verification-before-completion`, `requesting-code-review`. ## Global Constraints

- Port 3000. Env: `API_BASE_URL` (server side; in compose `http://gateway:8080`), `PUBLIC_API_BASE_URL` (browser, `https://api.craftoria.in`), `PUBLIC_SITE_URL`, `PUBLIC_MEDIA_BASE_URL`, `PUBLIC_PAYMENT_MODE` (`razorpay`|`fake`), `PUBLIC_FREE_SHIPPING_THRESHOLD_PAISE` (display only; must match order-service config), `PUBLIC_SENTRY_DSN?`.
- **No tokens in `localStorage`/`sessionStorage`.** The access token lives in module memory. On boot, `POST /v1/auth/refresh` (with `credentials:'include'` and `X-Requested-With: craftoria`) is called once (a deduped promise).
- The guest cart lives in `localStorage` key `cr_guest_cart_v1`: `{ items: {productId, qty, snapshot:{title, slug, pricePaise, imageUrl}}[] }`, merged via `POST /v1/cart/merge` on login, then cleared.
- Money is displayed only through `formatINR`. Copy follows the brand skill (e.g. buttons "Add to bag", "Pay ₹2,450").
- Routes:

  | Path | Kind | Notes |
  |---|---|---|
  | `/` | SSR | editorial home: featured crafts, categories, artisan stories |
  | `/c/:categorySlug` | SSR | browse with filters in the URL (`?minPrice&maxPrice&inStock&sort&page`) |
  | `/search` | SSR | `?q=` + the same filters; `noindex` |
  | `/p/:slug` | SSR | product detail, JSON-LD `Product`, OG tags |
  | `/artisans/:slug` | SSR | artisan profile + their products |
  | `/bag` | client | guest or user bag |
  | `/checkout` | client, auth + verified email | address → review → pay |
  | `/orders`, `/orders/:id` | client, auth | `?placed=1` polls until paid |
  | `/wishlist` | client, auth | |
  | `/account`, `/account/addresses`, `/account/security` | client, auth | profile, address book, password, delete account |
  | `/sell` | SSR landing + client form | artisan application |
  | `/login`, `/register`, `/forgot-password`, `/reset-password`, `/verify-email` | client | `?next=` redirect |
  | `/about`, `/shipping`, `/returns`, `/privacy`, `/terms`, `/contact` | SSR static | required by Razorpay KYC |
  | `/sitemap.xml`, `/robots.txt`, `/healthz` | resource routes | |

## Review Focus

1. Razorpay modal dismissed → the order stays `pending_payment`, the user sees "Payment not completed" with a working **Retry payment** (`POST /v1/orders/:id/payment`), and no duplicate order is created. (Task 7 test.)
2. A browser refresh on `/orders/:id?placed=1` while the webhook is still in flight keeps polling and shows "Confirming your payment…", never "failed". (Task 7 test.)
3. An expired access token mid-session: the request gets 401 → one silent refresh → retry; a refresh failure → redirect to `/login?next=`. (Task 2 test.)
4. Out-of-stock at checkout (409) shows which items and how many are available, and offers "Update bag". (Task 7 test.)
5. SSR pages must never contain personal data (they are CDN-cached). (Task 3 test `SSR html contains no user data`.)
